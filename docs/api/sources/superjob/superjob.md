## SuperJob (api.superjob.ru)

**Base URL:** `https://api.superjob.ru/2.0`  
**Формат ответов:** JSON, кодировка UTF-8  
**Официальная документация:** https://api.superjob.ru/register/ (доступна после регистрации)

### Аутентификация

Все запросы к `/vacancies/` требуют API-ключ приложения в заголовке.  
Справочные эндпоинты (`/towns/`, `/regions/`, `/catalogues/`) работают **без ключа**.

**Регистрация приложения:** https://api.superjob.ru/register/  
Нужен: `secret_key`. Хранится в конфиге через Options-паттерн, не в коде.

### Заголовки

| Заголовок | Значение | Обязательность |
|-----------|----------|----------------|
| `X-Api-App-Id` | `{secret_key}` | Обязателен для `/vacancies/` |

> Без заголовка API отвечает `403: Необходимо передать ключ приложения`.

### Rate Limits

Официальных лимитов нет в открытом доступе. Проект соблюдает **задержку 1–2 с** между запросами. При превышении частоты — `429` или временный бан IP.

## Справочные эндпоинты

### GET /towns/ — Города

Возвращает список всех городов. Используется для получения `id` города при поиске вакансий (параметр `town`).

**Запрос:**
```
GET https://api.superjob.ru/2.0/towns/?all=1
```

**Параметры:**

| Параметр | Значение | Описание |
|----------|----------|---------|
| `all` | `1` | Вернуть все города одним ответом без пагинации |

**Ответ:**
```json
{
  "objects": [
    {
      "id": 4,
      "id_region": 46,
      "id_country": 1,
      "title": "Москва",
      "title_eng": "Moscow"
    },
    {
      "id": 14,
      "id_region": 41,
      "id_country": 1,
      "title": "Санкт-Петербург",
      "title_eng": "Saint-Petersburg"
    }
  ]
}
```

**Ключевые поля:**

| Поле | Тип | Описание |
|------|-----|---------|
| `id` | int | Идентификатор города — передаётся в параметре `town` при поиске вакансий |
| `id_region` | int | ID региона (из `/regions/`) |
| `title` | string | Название города |

### GET /regions/ — Регионы

Справочник регионов. Используется, когда нужно охватить весь регион (параметр `id_region` при поиске), а не конкретный город.

**Запрос:**
```
GET https://api.superjob.ru/2.0/regions/?all=1
```

**Ответ:**
```json
{
  "objects": [
    { "id": 46, "id_country": 1, "title": "Московская область" },
    { "id": 41, "id_country": 1, "title": "Ленинградская область" }
  ]
}
```

> Всего 104 региона. Для аналитики используем `town` (город), а не `id_region`.


## Поиск вакансий

### GET /vacancies/ — Поиск вакансий

Основной эндпоинт для сбора рыночных данных. **Требует `X-Api-App-Id`** в заголовке.

**Запрос:**
```
GET https://api.superjob.ru/2.0/vacancies/
X-Api-App-Id: {secret_key}
```

**Параметры фильтрации (используемые в проекте):**

| Параметр | Тип | Описание |
|----------|-----|---------|
| `keyword` | string | Ключевые слова для поиска в названии/тексте вакансии |
| `catalogues` | int | `key` специализации из `/catalogues/` |
| `town` | int | `id` города из `/towns/` |
| `experience` | int | Опыт работы (см. таблицу ниже) |
| `no_agreement` | int | `1` — только вакансии с указанной зарплатой |
| `date_published_from` | int | Unix-timestamp: публикация не раньше |
| `date_published_to` | int | Unix-timestamp: публикация не позже |
| `count` | int | Вакансий на страницу (макс. `100`) |
| `page` | int | Номер страницы (с `0`) |
| `order_field` | string | Поле сортировки: `date` (по дате), `payment` (по зарплате) |
| `order_direction` | string | `asc` / `desc` |

**Значения параметра `experience`:**

| ID | Описание |
|----|---------|
| `1` | Без опыта |
| `2` | От 1 до 3 лет |
| `3` | От 3 до 6 лет |
| `4` | Более 6 лет |

> Фильтр по `experience` соответствует полю `experience.id` в объекте вакансии.

**Ответ:**

```json
{
  "total": 1247,
  "more": true,
  "objects": [
    {
      "id": 98765432,
      "profession": "Python Backend Developer",
      "payment_from": 180000,
      "payment_to": 250000,
      "currency": "rub",
      "firm_name": "Acme Corp",
      "firm_id": "42",
      "town": { "id": 4, "title": "Москва" },
      "experience": { "id": 2, "title": "От 1 года до 3 лет" },
      "type_of_work": { "id": 6, "title": "Гибкий график" },
      "place_of_work": { "id": 2, "title": "Удалённая работа" },
      "candidat": "Требования: знание Python, PostgreSQL, опыт с Docker...",
      "link": "https://www.superjob.ru/vakansii/python-backend-developer-98765432.html",
      "date_published": 1751050000
    }
  ]
}
```

**Ключевые поля ответа:**

| Поле | Тип | Описание |
|------|-----|---------|
| `total` | int | Общее число вакансий по запросу (аналог `found` в HH) |
| `more` | bool | `true` — есть следующая страница |
| `objects` | array | Список вакансий на текущей странице |

**Ключевые поля объекта вакансии:**

| Поле | Тип | Описание |
|------|-----|---------|
| `id` | int | Уникальный ID вакансии |
| `profession` | string | Название вакансии (аналог `name` в HH) |
| `payment_from` | int | Минимальная зарплата (`0` = не указана) |
| `payment_to` | int | Максимальная зарплата (`0` = не указана) |
| `currency` | string | Код валюты: `rub`, `usd`, `eur`, `uah`, `kzt` |
| `firm_name` | string | Название компании (аналог `employer.name` в HH) |
| `firm_id` | string | ID компании (аналог `employer.id` в HH) |
| `town` | object | Город `{id: int, title: string}` |
| `experience` | object | Опыт `{id: int, title: string}` |
| `type_of_work` | object | График работы `{id: int, title: string}` |
| `place_of_work` | object | Место работы `{id: int, title: string}` |
| `candidat` | string | Текст требований к кандидату — **источник навыков** (нет структурированного поля `key_skills`) |
| `link` | string | URL вакансии на сайте SuperJob |
| `date_published` | int | Дата публикации в Unix timestamp |

> `payment_from = 0` и `payment_to = 0` означает, что зарплата не указана. Параметр `no_agreement=1` отсекает такие вакансии на стороне API.

**Пагинация:**

SuperJob не имеет жёсткого лимита на общее число страниц (в отличие от HH с лимитом 2000). Итерация продолжается, пока `more = true` или `page * count < total`. При больших выборках — разбивать по `catalogues` или `date_published_from`/`date_published_to`.

## Навыки — особенность SuperJob

В отличие от HH.ru, SuperJob **не возвращает структурированный список навыков** (`key_skills`). Навыки находятся в текстовом поле `candidat` — описание требований к кандидату в произвольном формате.

**Подход к извлечению навыков:**

Парсить `candidat` регулярными выражениями или NLP по заранее составленному словарю ключевых слов:

```
"candidat": "Требования: Python 3.x, PostgreSQL, Redis, Docker, опыт работы с REST API..."
```

→ матчим по списку `["Python", "PostgreSQL", "Redis", "Docker", "REST API", ...]`  
→ считаем частоту упоминаний по выборке вакансий.

Это ключевое отличие от HH, где `key_skills` — структурированный массив объектов.

## Сценарии сбора данных

### Зарплатная вилка по срезу (роль × грейд × регион)

```
GET /vacancies/
  ?catalogues={key}          ← специализация из /catalogues/
  &town={id}                 ← город из /towns/
  &experience={1|2|3|4}      ← повторить для каждого грейда
  &no_agreement=1             ← только вакансии с указанной зарплатой
  &count=100
  &page={0..N}
```

→ Из каждого объекта берём `payment_from`, `payment_to`, `currency`.  
→ Если `payment_from = 0` — используем только `payment_to`, и наоборот.  
→ Конвертируем в рубли (если `currency != "rub"`).  
→ Агрегируем P25 / Median / P75 в памяти → `SalaryAggregate`.

---

### Количество активных вакансий / спрос

```
GET /vacancies/
  ?catalogues={key}
  &town={id}
  &count=1
```

→ `response.total` — число активных вакансий без скачивания страниц → `MarketSnapshot.TotalVacancies`.

Для тренда по периодам:

```
GET /vacancies/
  ?catalogues={key}
  &town={id}
  &date_published_from={unix_timestamp}
  &date_published_to={unix_timestamp}
  &count=1
```

→ `response.total` = число вакансий за период.

---

### Новые вакансии за период

```
GET /vacancies/
  ?catalogues={key}
  &town={id}
  &date_published_from={вчера 00:00 UTC в unix}
  &date_published_to={вчера 23:59 UTC в unix}
  &order_field=date
  &order_direction=desc
  &count=100
  &page={0..N}
```

→ `date_published` из каждого объекта — Unix timestamp.  
→ Считаем `delta` за период.

---

### Навыки — частота требований

```
GET /vacancies/
  ?catalogues={key}
  &town={id}
  &count=100
  &page={0..4}          ← первые 500 вакансий достаточно
```

→ Для каждого объекта берём поле `candidat`.  
→ Матчим по словарю навыков регулярками.  
→ Считаем `MentionCount` и `MentionRate` по всей выборке → `SkillStat`.

> Не нужен отдельный запрос по ID — всё в основном листинге. Это быстрее, чем HH.

---

### Работодатели / доля рынка

```
GET /vacancies/
  ?catalogues={key}
  &town={id}
  &count=100
  &page={0..N}
```

→ `firm_name` + `firm_id` из каждого объекта.  
→ Считаем `VacancyCount` как частоту `firm_id` в выборке.  
→ `MarketShare = VacancyCount / total`.

SuperJob **не имеет публичного эндпоинта** для профиля компании, аналогичного `GET /employers/{id}` в HH. Дополнительных данных по работодателю не получить без специального доступа.

## Сравнение с HH.ru

| Аспект | HH.ru | SuperJob |
|--------|-------|---------|
| Аутентификация | OAuth2 `client_credentials` | API-ключ в заголовке `X-Api-App-Id` |
| Навыки | Структурированный `key_skills[]` — нужен `GET /vacancies/{id}` | Текст в `candidat` — парсим регулярками из основного листинга |
| Зарплата | `salary.from` / `salary.to`, `salary.gross` | `payment_from` / `payment_to`; gross не указывается |
| Фильтр «только с зарплатой» | `only_with_salary=true` | `no_agreement=1` |
| Лимит пагинации | 2000 вакансий (20 стр × 100) | Нет жёсткого лимита |
| Профиль компании | `GET /employers/{id}` | Нет публичного эндпоинта |
| Справочник ролей | `GET /professional_roles` (иерархия `category → role`) | `GET /catalogues/` (иерархия `category → position`) |
| Справочник городов | `GET /areas` (дерево: страна → регион → город) | `GET /towns/` + `GET /regions/` (плоские списки) |
| Дата публикации | ISO 8601 строка (`published_at`) | Unix timestamp (`date_published`) |
