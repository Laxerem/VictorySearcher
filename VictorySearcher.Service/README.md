# VictorySearcher.Service

**VictorySearcher.Service** — бэкенд внутреннего HR-инструмента VictorySearcher: серверная часть монорепозитория, которая держит всю бизнес-логику, данные и интеграции и отдаёт наружу REST API. Пользовательского интерфейса не имеет (фронтенд — `VictorySearcher.Web`). См. также [корневой README](../README.md).

## О проекте 🏗

Сервис автоматизирует две HR-задачи: оценку резюме под конкретную вакансию с помощью LLM и (планируется) сбор аналитики рынка труда. Тяжёлые операции вынесены в фоновые задачи, поэтому API остаётся отзывчивым, а результаты появляются по мере готовности.

### Чем занимается

- **Скоринг резюме.** Рекрутёр создаёт вакансию (заголовок, описание, требования, доп. требования) и загружает резюме (`.txt`, `.docx`, `.pdf`). Фоновая задача парсит текст и оценивает каждое резюме через LLM, выдавая общий балл, разбивку (опыт / навыки / доп. требования), обоснование на русском и разбор по пунктам требований. За ходом можно следить в реальном времени, итог — ранжированный список кандидатов. Скоринг инкрементный: повторный запуск обрабатывает только новые, ещё не оценённые резюме.
- **Аналитика рынка труда.** Автономный сбор вакансий с HH и SuperJob по расписанию. *Запланировано, пока не реализовано.*

### Доступ

Аутентификация — единственный пользователь из seed. Все эндпоинты, кроме логина, защищены JWT (`Authorization: Bearer <token>`).

### Архитектура

Clean Architecture, 4 проекта со строгим направлением зависимостей внутрь: `Domain ← Application ← Infrastructure / Api`. `Domain` ни на что не ссылается. Подробно о слоях и соглашениях — в [`docs/ARCHITECTURE.md`](../docs/ARCHITECTURE.md) и [`CLAUDE.md`](CLAUDE.md).

## Как работает скоринг

Скоринг асинхронный: `POST .../scoring` лишь создаёт `ScoringRequest` и ставит фоновую задачу Hangfire, сразу возвращая `requestId`. Дальше задача (`ScoringExecutor`) идёт по конвейеру:

1. Берёт **только неоценённые** резюме вакансии (инкрементность).
2. Извлекает текст каждого резюме нужным парсером (`.txt` / `.docx` / `.pdf`).
3. Отдаёт текст и контекст вакансии в `ResumeAnalyserService` — оценку через LLM (см. ниже).
4. Сохраняет `ScoringResult` и шлёт событие прогресса `checked/total` (его читает SSE-стрим).

Статусы запроса: `Pending → InProcess → Finished | Failed`.

### **Оценка устойчива к недетерминированности модели.**
LLM вызывается несколько раз параллельно (по умолчанию 3) с единым системным промптом, который задаёт рубрику и строгую JSON-схему и требует опираться **только на факты из резюме**. 

Каждый ран возвращает под-оценки `experience` / `skills` / `extra` (0–100) и разбор по требованиям (`covered` + цитата-подтверждение). По ранам берётся **медиана**, итоговый `overallScore` — взвешенная сумма под-оценок (опыт · 0.5 + навыки · 0.35 + доп. · 0.15, веса настраиваются; считается на стороне сервиса, не моделью). 

Если раны сильно разошлись или часть вызовов упала, результат помечается `IsUncertain` — сигнал перепроверить вручную.

Результаты (`GET .../scoring/results`) возвращаются по последнему скорингу каждого резюме, отсортированные по убыванию балла. Параметры конвейера настраиваются в секции `ResumeAnalyser` (см. [Как запустить](#как-запустить)).

## API

| Метод | Маршрут | Назначение |
|-------|---------|-----------|
| POST | `/api/auth/login` | Логин, выдаёт JWT |
| POST · GET | `/api/vacancies` | Создать вакансию · список вакансий |
| GET | `/api/vacancies/{id}` | Детали вакансии |
| POST · GET | `/api/vacancies/{id}/resumes` | Загрузить резюме (multipart) · список с пагинацией |
| GET | `/api/vacancies/{id}/resumes/{resumeId}/content` | Извлечённый текст резюме |
| GET | `/api/vacancies/{id}/resumes/{resumeId}/download` | Оригинальный файл |
| POST | `/api/vacancies/{id}/scoring` | Запустить скоринг (Hangfire-джоб) |
| GET | `/api/vacancies/{id}/scoring/status` | Текущий статус скоринга |
| GET | `/api/vacancies/{id}/scoring/results` | Результаты, отсортированные по баллу |
| GET | `/api/vacancies/{id}/scoring/stream` | Прогресс скоринга в реальном времени (SSE) |

Интерактивная схема API — Swagger UI на `/swagger`, дашборд фоновых задач — на `/hangfire`.

## Как запустить

Проще всего — через Docker Compose из корня репозитория (поднимает API + PostgreSQL):

```bash
cd ..
cp .env.example .env   # заполнить ключ LLM и учётные данные
docker compose up -d
```

API будет доступен на `http://localhost:5000` (контейнер слушает `8080`).

Локально (нужны установленный .NET 9 SDK и доступная PostgreSQL):

```bash
dotnet build VictorySearcher.Service.slnx
dotnet run --project VictorySearcher.Service.Api
```

### Конфигурация

Настройки задаются через `appsettings.json` и переменные окружения (Options-паттерн). Ключевые группы — см. [`.env.example`](../.env.example):

- `Jwt__*` — секрет и учётные данные единственного пользователя
- `Llm__*` — `ApiKey`, `BaseUrl`, `ModelId` провайдера LLM
- `ResumeAnalyser__*` — параметры скоринга: веса под-оценок, число ранов (`Runs`), порог неопределённости, системный промпт
- `ConnectionStrings__Postgres` — строка подключения к БД
- `Storage__UploadsPath` — каталог хранения загруженных резюме

### Миграции

```bash
dotnet ef migrations add <Name> \
  -p VictorySearcher.Service.Infrastructure \
  -s VictorySearcher.Service.Api
```
