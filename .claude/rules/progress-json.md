# progress.json — Rules

`progress` — массив коротких предложений, описывающих что реализовано. Один элемент на сервис/компонент.

## Когда обновлять

- После реализации чего-либо с видимым для пользователя результатом
- После крупных изменений, которые затрагивают бизнес-логику


## Формат

```json
{
  "project": "service name",
  "items":
    [
      {
        "date": "yyyy-mm-dd",
        "progress": [ // список изменений
          
        ]
      }
    ]
}
```

## Как писать

- Формат: `"Реализован(а) <что> в <ServiceName>: <что конкретно умеет>"`
- Если запись для сервиса уже есть — заменить её целиком, не добавлять новую
- Если сервиса ещё нет — добавить новый элемент в конец массива
- Создавать новый json элемент поле `""` на текущую дату

## Пример

Плохо: `"Рефакторинг стиля кода в соотвествии с K&R"`  
Хорошо: `"Реализована авторизация в AuthService: регистрация, вход, email-подтверждение, refresh-токен"`
Хорошо: `Рефакторинг AuthService: замена EDD на Result<T>"`
