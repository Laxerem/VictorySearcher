Корневой `README.md` пишется для людей-проверяющих стажировки и должен **демонстрировать, как пользователь управляет ИИ-агентами** (какие агенты, как устроен процесс, как агенты подгружают скиллы/правила). Для этой компании навык оркестрации агентов — ключевой сигнал.

**Why:** `docs/TASK.md` и `docs/ARCHITECTURE.md` написаны как контекст для агентов, а не для людей — ссылаться на них из «человеческого» README не нужно. Детали продукта (например, как работает скоринг) — в README соответствующего сервиса, не в корневом.

**How to apply:** В корневой README не класть подробности реализации продукта и не ссылаться на agent-facing доки. Вместо этого раскрывать процесс работы с Claude: набор агентов и их роли, скиллы/правила и как они загружаются, память агентов, артефакты (`CLAUDE.md` по git-истории, `docs/ai-collaboration.md`). Продуктовую начинку (скоринг и пр.) держать в README сервиса.
